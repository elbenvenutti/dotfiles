# PR Description Concise

## Purpose
Produce review-friendly PR descriptions without redundant noise.

## When to load
- Creating or updating pull request descriptions.

## Non-negotiable rules
- Be concise and scannable.
- Focus on what changed and why.
- Do not include lint/test/checklist status already visible in CI.
- Avoid obvious or repetitive statements.

## Recommended format
- Brief context sentence.
- 1-3 bullets of key changes.
- Optional impact note (migration, risk, rollout).
